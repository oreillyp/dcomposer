Raw data for scripts/prepare_training_data.py:

oneshots/
  kick/       (at least three recordings per included class)
  snare/
  hat/
  ...
midi/
  train/*.mid
  val/*.mid

Drum notes must be on MIDI channel 10 (zero-based channel 9), using General
MIDI drum pitches. Samples must cover every recognized class in the scores.
Supported classes: kick, snare, rim, clap, hat, tom, cymbal, tambourine,
cowbell, shaker, perc, other. Audio paths in CSVs must be absolute.
MIDI train/val directories must be disjoint.

Label hierarchy
---------------
The default D-Composer recipe uses OneShotMidiDataset.hierarchy_level: coarse.
Coarse labels are the drum families listed above; rim and clap remain separate
from snare. Fine labels distinguish hat_closed/hat_pedal/hat_open, tom_low/
tom_mid/tom_high, crash/ride/splash, and individual percussion types. The mapping
is defined in dcomposer/constants.py.

Fine training is implemented: set OneShotMidiDataset.hierarchy_level: fine and
provide canonical midi_fine_note values in the sample CSVs. MIDI scores must
have samples for each fine class they use. The model vocabulary already includes
these notes; changing hierarchy does not require changing DComposer.n_vocab.
The generic folder preparation labels families only. It does not infer fine
classes. Transcription evaluation merges predictions to the paper's five classes.

One-shot CSVs
-------------
oneshots.csv demonstrates the supported columns; optional cells may be empty.
Required for the default recipes:
  oneshot       Audio path.
  label         DOC sampling label (OneShotDataset.label_col); normally the family.
  coarse_label  D-Composer family, from the supported class list above.

Optional annotations:
  fine_label       Canonical subtype, e.g. hat_open.
  midi_fine_note   Canonical GM note, e.g. 46 for hat_open; required in fine mode.
  midi_coarse_note Family's canonical note, e.g. 42 for hat; informational.
  kit_name         Groups samples from a single kit; empty means no kit assignment.
  source_dataset, source_family  Provenance.
  duration, sample_rate, channel_count, filename, subdir  Audio/file metadata.
  midi_note, midi_note_source, velocity_layer  Additional source annotations.
Other metadata columns are allowed. Audio properties are read from the actual file.

Packed-audio columns (generated by preparation; required for packed loading):
  packed_audio_path          Raw interleaved float32 file, not a WAV.
  packed_audio_offset        Starting audio frame, not byte offset.
  packed_audio_num_frames    Number of frames for this sample.
  packed_audio_num_channels  Channels per frame.
  packed_audio_sample_rate   Sampling rate in Hz.
  packed_audio_dtype         float32.

Without packed files, set train/OneShotDataset.audio_backend and
val/OneShotDataset.audio_backend to file for DOC, and
OneShotMidiDataset.audio_backend to file for D-Composer. For alternative DOC
recipes, change their corresponding OneShotDataset.audio_backend settings.

Cached MIDI CSVs
---------------
Generated by scripts/setup/create_midi_manifests.py, not written by hand:
  midi_txt, midi_idx_npy, midi_row  Required event text, line index, and row number.
  source_midi, source_dataset     Optional provenance.
  n_events, duration_steps, duration  Optional event count/length metadata.
The event text stores onset-step, GM-note, velocity triples at 100 steps/second.

Generated files (not tracked):
manifests/training/
  oneshots_train.csv
  oneshots_val.csv
  oneshots_test.csv
  midi_train.csv
  midi_val.csv
  midi_train.txt, midi_train.idx.npy  (local MIDI event cache)
  midi_val.txt, midi_val.idx.npy
  groove_train.csv, groove_val.csv

prepare_training_data.py refuses to overwrite an output directory containing
prepared CSVs or MIDI caches. Use a different --output directory for another
collection and update the config's manifest paths accordingly.
